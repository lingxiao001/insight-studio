# 自托管安全指南

漏洞报告流程见根目录 [SECURITY.md](../SECURITY.md)。本页说明部署与数据边界，不代表完整安全认证。

## 凭据与访问

真实 `.env`、访问配置、数据库、上传、模型密钥、备份和供应商响应不进入 Git。初始管理员密码需唯一且足够长；`SESSION_SECRET` 至少 32 字符并持久保存。生产通过 HTTPS 访问，启用 Secure Cookie，应用端口仅监听回环。

只有管理员能验证和更换共享后端模型密钥。前端从不读取已存密钥，不应把它放入 `VITE_*`、构建产物、截图或公开日志。密钥目录为 700、文件为 600；备份同样包含秘密，须限制访问。

账号隔离通过服务端拥有者条件实现，不能依赖前端隐藏按钮。当前没有邮件验证或密码找回，也不能识别同一自然人的多个账号。开放注册会让新账号各获得 1 USD 应用模型额度，运营者需自行选择身份或邀请控制；供应商后台预算仍应单独管理。

## 文件与报告

上传限制、ZIP 路径检查、展开大小限制和格式检查降低部分风险，不代替主机补丁与资源隔离。当前工作队列适合小规模单实例；不要把内置队列当作公共大规模计算平台。

数据保存在实例磁盘。报告含预览、本地类别文本和统计极值，即使只分享 HTML 也可能泄露敏感内容。分享前审查结果，删除账号任务不等于抹除私有备份，也不会删除费用记录。

HTML/Markdown 输出对数据文本转义，模型文本不执行。仍应把用户目标、列名和数据值视为不可信输入，不给外部模型执行工具、读取其他账号数据或运行代码的能力。

## 外部模型

模型只接收列名、目标和有界聚合，原始行、预览和类别原值不发送。小样本组、极值或敏感列名仍可能被推断，汇总不是匿名保证。使用者应在启用模型前确认传输许可。

请求要求 ZDR、指定供应商与价格上限；无法核验时停止模型调用。这些约束依赖外部服务，部署者仍需核对其政策及账户配置。模型解释可能不正确；保守风险检查不能保证事实、合规或决策适用性。

## 发布前检查

核对 Git 跟踪文件、构建产物和图片，确认不包含真实密码、密钥、私有用户名、服务器地址、访问文件、数据库、报告原始行或备份。使用公开数据制作截图时保留来源，并明确演示数据、真实数据和离线重放的区别。出现凭据暴露时先撤销与轮换，再处理公开历史；只删除当前文件不能撤回已经泄露的秘密。
