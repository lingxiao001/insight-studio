# Agent 分析流程

这里的 Agent 是受约束的六步分析流程。数据计算由固定 Python 模块执行，可选模型只解释经过筛选的证据，不接触文件系统，不生成或执行 Python，不自动训练模型。

| 步骤 | 内容 | 产物 |
| --- | --- | --- |
| 读取 | 文件安全检查、编码与工作表选择、范围限制 | 数据表与来源说明 |
| 画像 | 列类型、缺失、唯一值与基本统计 | 全字段画像 |
| 质量 | 缺失、重复、常量与潜在异常 | 质量指标与注意事项 |
| 图表 | 七个专题的确定性字段/图表选择 | Plotly 图表与 EDA 证据 |
| 洞察 | 统计规则生成描述；可选一次模型解释 | 证据、建议、模型状态 |
| 报告 | 保存 JSON、Markdown、独立 HTML | 前端可读看板与下载 |

## 统计与模型的分工

内置统计洞察直接引用数值、分母和样本范围。统计模块只描述相关和条件比较，不将它们解释为因果。模型可以结合用户目标组织文字、提出后续验证建议，但其结论仍需核对统计证据和字段业务含义。

日期文本仅在所有非缺失值都可解析时转换，统一到 UTC。关注字段会影响深入探索的优先级，不代表自动进行监督学习。读取、字段选择、显示抽点和模型证据裁剪分别标注，避免把局部分析当作全量穷举。

## 模型输入

发送列名、类型、质量和有界统计证据，以及用户目标。不会发送原始文件、原始行、前端预览或原始类别标签。分组类别使用稳定别名，例如 `G01`；标签映射仅留在本地结果。

证据最多包括 8 项分布、每种相关方法 8 对变量、5 项分组研究（每项最多 6 组，优先关注指标）、3 项日期研究的最近 12 个有有效指标桶。日期有效分母和解释 notes 同时发送。目标文本另有长度限制；序列化证据限制为 32,000 字符，过大时进一步裁剪，仍不能满足则跳过模型。

不发送原始行不等于匿名。列名、用户目标、极值、小组统计和缺失模式仍可能透露敏感信息。需要外部模型前，上传者应确认这些汇总可以交给配置的服务商处理。

## 请求、预算与输出

只有任务明确启用模型且当前用户费用检查通过时，才发送一次推理。服务端核验固定配置端点、价格上限、参数能力和 ZDR，禁用自动模型/供应商回退，设置 `reasoning.effort='none'` 和 `max_tokens=3200`。预留与结算见[模型与计费](model-and-budget.md)。

提示要求简洁完整 JSON，目标约 1,800 tokens：摘要约 80 字以内、正文 300–450 字、最多三条模型洞察及三条建议。提示字数是写作目标；接受端使用较宽的防滥用安全边界，避免在句中截掉限定语。最终洞察数组还包含统计洞察，数量可能超过三条。

输出需通过 JSON 结构、字段长度及已知高风险断言检查。后者保守检查缺少依据的形状/关键因素、未检验的显著性与空间价格方向断言；局部否定或待验证建议可以通过。命中后整批不采用模型新增文字，保留统计结果，在 Agent 过程说明原因及费用状态，不自动重试。

该检查不是全面事实核验，不能验证每个数字、排名、阈值、单位或业务解释。模型正常返回且未被拦截不等于语义正确。模型内容在前端以文字显示，导出会转义；不执行其指令。

## 失败与复核

超时、成本缺失、截断和不合格文本均保留统计报告。实际发生的成本仍需结算，账单未知则保留预留。前端明确显示模型解释未采用，并可查看 Agent 过程。重新分析先让用户选择，默认免费统计，没有自动付费重试。

部分结果可带人工复核元数据 `agent.review` 和公开 notes。这只是该份结果的审查记录，不是所有报告已复核的保证。复核发现错误时应明确更正或撤下误导文字，并保留审计记录；不因删除报告而重置费用。
